# M5a plan: OAuth 2.1 server, password consent, tokens in Postgres, daily cleanup cron

Written by an Opus planning pass; approved by the owner with one change: **the consent page asks for `APP_PASSWORD`, not a separate PIN.** It reuses the M3 login check and the same `login` lockout key (5 fails, 15 min). There is no `OAUTH_PIN` and no `pin` key. Production `APP_ORIGIN` is `https://sound-journal.vercel.app`. All other design calls below are approved.

No migration: the existing OAuth tables (`oauth_clients`, `oauth_codes`, `oauth_grants`, `oauth_tokens`, `auth_attempts`) already have every column needed. No new dependencies. Macro-log source is not available; design follows the docs plus RFC 6749/7591/7636/8414/8707/9207/9728 and OAuth 2.1.

## Files

New:
- `lib/auth/crypto.ts`: `randomToken(bytes=32)` (base64url), `sha256Hex`, `pkceS256`, `safeEqual` (sha256 both, then timingSafeEqual).
- `lib/auth/oauth-metadata.ts`: `appOrigin(env)` (trim, strip trailing slash; https only, http only for localhost/127.0.0.1; else null), `mcpResource(origin)` = `${origin}/api/mcp`, `authorizationServerMetadata`, `protectedResourceMetadata`. AS doc: issuer, `/oauth/authorize`, `/api/oauth/token`, `/api/oauth/register`, response_types `["code"]`, grant_types `["authorization_code","refresh_token"]`, `code_challenge_methods_supported: ["S256"]`, `token_endpoint_auth_methods_supported: ["none"]`, `authorization_response_iss_parameter_supported: true`. Resource doc: resource `${origin}/api/mcp`, authorization_servers `[origin]`, bearer_methods `["header"]`. If `APP_ORIGIN` unset/invalid, discovery returns 503 (fail closed).
- `lib/auth/cron.ts`: `isCronAuthorized(secret, authorization)`: false if secret missing/empty/shorter than 16; else `safeEqual("Bearer "+secret, authorization ?? "")`, exact string.
- `lib/core/oauth-rules.ts` (pure): limits (10 redirect URIs, 2000 URI length, 100 name, 2048 state, 10 KB registration body); `isAllowedRedirectUri` (absolute URL; https, or http only for localhost/127.0.0.1/[::1]; no fragment, userinfo, whitespace/control chars); `isValidCodeChallenge` (`^[A-Za-z0-9_-]{43}$`); `isValidCodeVerifier` (`^[A-Za-z0-9\-._~]{43,128}$`); `parseRegistration` (1-10 redirect URIs; auth method absent or `none`; grant_types subset of authorization_code/refresh_token; response_types subset of code; name stripped of control chars, capped, default "MCP client"; unknown fields dropped); `readAuthorizeParams`; `buildRedirect` (URL.searchParams.set, keeps existing query).
- `lib/core/oauth.ts`: constants (code 60s, access 1h, refresh 90d sliding, MAX_CLIENTS 200, ORPHAN_CLIENT_DAYS 7, last-used throttle 300s); `registerClient` (re-check URIs, refuse past MAX_CLIENTS, uuid id, URIs stored verbatim); `getClient`; `checkAuthorizeRequest` (1. client must exist else no-redirect `invalid_client`; 2. `redirect_uri` required, exact `===` match else no-redirect `invalid_redirect_uri`; 3. only then redirectable errors: response_type != code, method != exactly `S256` (missing is rejected), bad challenge, state too long, `resource` present and != mcpResource (ignore one trailing slash) -> `invalid_target`); `issueAuthorizationCode` (raw 256-bit, store only sha256, 60s); `exchangeAuthorizationCode` (one transaction; `DELETE ... RETURNING` consumes the code atomically so a failed attempt still burns it; checks expiry, client_id, exact redirect_uri, PKCE via safeEqual; on success lock client row, delete existing grants for (client,user), insert grant + access token (+1h) + refresh token (+90d), hashes only); `refreshAccessToken` (one transaction, token joined to grant FOR UPDATE; must be kind refresh, unexpired, same client; `used_at` set means replay: delete the grant (cascade) and return invalid_grant, committed; else mark used, insert new pair, set grant `last_used_at`); `verifyAccessToken` (kind access, unexpired; throttled `last_used_at`; returns `{userId, grantId, clientId, clientName}` or null; for M5b); `listGrants`, `revokeGrant` (user scoped, CoreError not_found).
- `lib/core/cleanup.ts`: `purgeDeleted(db, userId, now)` in one transaction, cutoff = now - 30x86400s, strict `<`: `SELECT id FROM entries WHERE user_id AND deleted_at < cutoff ORDER BY id FOR UPDATE`; delete highlights `WHERE user_id AND (deleted_at < cutoff OR entry_id = ANY(<literal id array>)) RETURNING id` (literal array, NOT a subquery, so a concurrently restored entry is not wrongly purged); delete those entries; tags and artists untouched; return highlight ids (for M6b vector deletion). `cleanupExpiredAuth` (global): expired codes, expired tokens (used-but-unexpired refresh tokens stay for replay detection), grants with no tokens, clients with no grants/codes and created more than 7 days ago, `auth_attempts` rows with `locked_until <= now`. `runDailyCleanup`: per-user `purgeDeleted` over all users, then `cleanupExpiredAuth`.
- `lib/http/cors.ts`, `lib/http/oauth.ts`, `lib/http/cron.ts`: handlers take an injected `db` and env so they test on PGlite (route files only export HTTP verbs and stay one-liners with `dynamic = "force-dynamic"`). `handleRegister` (413 over 10 KB, 400 bad JSON, 201 with no secret, CORS `*`); `handleToken` (form-urlencoded only; authorization_code needs code, client_id, redirect_uri, code_verifier; refresh_token needs refresh_token, client_id; else unsupported_grant_type; client_id from body or Basic username, mismatch -> invalid_client; unknown client 401; `Cache-Control: no-store`); `handleConsent` (foreign Origin -> 403; re-run `checkAuthorizeRequest` on posted fields, never trust hidden fields; no-redirect errors -> 400; redirectable errors -> 303; deny -> 303 `access_denied` with state and `iss`; password via **`attemptLogin(db, APP_PASSWORD, given)`** (same `login` key and lockout as the login form); locked/invalid -> 303 back to `/oauth/authorize?<validated params>&auth_error=locked|invalid`; unset `APP_PASSWORD` -> config error; ok -> `issueAuthorizationCode(db, OWNER_USER_ID, ...)` then 303 to `redirect_uri?code&state&iss`); `handleCleanup` (401 before any DB call unless `isCronAuthorized`; 200 with counts only; never log tokens, codes, password, or the secret).
- Routes: `app/.well-known/oauth-authorization-server/route.ts` (GET, OPTIONS); `app/.well-known/oauth-protected-resource/[[...path]]/route.ts` (GET, OPTIONS; serves `/` and `/api/mcp`, other sub-paths 404); `app/api/oauth/register/route.ts`; `app/api/oauth/token/route.ts`; `app/api/oauth/authorize/route.ts` (POST consent); `app/oauth/authorize/page.tsx` (server component: no-redirect errors render a message; redirectable errors `redirect(...)`; valid shows client name labelled "name given by the app, not verified", the **redirect host prominently**, a "only approve if you just started connecting" warning, a password field (`type=password`), Approve/Deny buttons >= 44px, hidden validated params; "not configured" if `APP_ORIGIN` or `APP_PASSWORD` unset); `app/api/cron/cleanup/route.ts` (GET).

## Security checklist (reviewer will verify)
S256 only (missing/`plain` rejected); exact `===` redirect match at authorize and token, client and redirect validated before any redirect; codes 256-bit, hash only, 60s, consumed by DELETE RETURNING even on failure, bound to client + redirect + challenge; tokens 256-bit, hash only, kind checked on every use; refresh rotation with replay revoking the grant; consent password via the transactional locked `attemptLogin`, locked key refuses even the correct password; cron fails closed on unset/empty/short secret, constant time, no DB before auth; purge scoped by `user_id`, entries locked first, literal id array; CORS `*` only on discovery/register/token; consent page cannot be framed; **nothing session-gated may live under `/api/oauth/*`** (put any future "connected apps" routes under e.g. `/api/connections/*`).
